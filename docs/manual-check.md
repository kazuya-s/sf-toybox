# 手での確認の手順 — U1 土台と件数の切り替え

自動テスト（`npm run test -- --coverage`）とビルドの確認（`npm run check:manifest`）が通ったあとに、開発者組織か Sandbox で、ビルドした拡張機能を手で動かして確かめます（team.md「Walking Skeleton」「Testing Posture」）。公開の流れの 2 番目の手順です（cicd-pipeline.md「公開の流れ」）。

確かめた結果は、日付・組織の種類（開発者組織／Sandbox）・Chrome の版と一緒に記録します。

## 0. 用意

- Chrome 120 以降
- Salesforce の開発者組織か Sandbox に、システム管理者でログインできること
- 手元でビルドしたもの: `npm ci` → `npm run build`（出力は `.output/chrome-mv3/`）

## 1. 拡張機能の読み込み方

1. Chrome で `chrome://extensions` を開く。
2. 右上の「デベロッパー モード」を ON にする。
3. 「パッケージ化されていない拡張機能を読み込む」を押し、`.output/chrome-mv3/` のフォルダを選ぶ。
4. 一覧に「sf-toybox」が出て、エラーの表示がないことを確かめる。
5. 「詳細」を開き、権限の表示が「Salesforce の 3 つのドメインのデータの読み取りと変更」相当だけであること、`docs/store/permissions.md` の内容と食い違いがないことを確かめる。
6. ビルドし直したときは、拡張機能の「再読み込み」ボタンを押してから、Salesforce の画面も再読み込みする。

## 2. 件数バーの確認（US2.1）

Lightning Experience の設定画面から、古い形式の一覧画面を開いて確かめます。

1. 設定 →「Apex クラス」を開く（ほかに「Visualforce ページ」「静的リソース」など、一覧の下にページ送りがある画面）。
2. 一覧の表のすぐ上に、「表示件数 [100][500][1000][2000] [件数を入力][表示]」の件数バーが出ることを確かめる（AC2.1.1）。
3. 「500」を押すと、その一覧だけが開き直り、URL の `rowsperpage` が 500 になり、「500」のボタンが強調されることを確かめる（AC2.1.2、AC2.1.6）。
   - フレームの URL は、件数バーの上で右クリック →「フレームのソースを表示」などで確かめる。
4. 入力欄に `3000` を入れて Enter を押すと、`rowsperpage=3000` で開き直ることを確かめる（AC2.1.3）。
5. `0`、`-5`、`1.5`、`abc`、空のそれぞれで Enter を押し、開き直さず「1 以上の整数を入力してください」が出て、入力した文字が残ることを確かめる（AC2.1.4）。
6. ほかのパラメータ（`setupid` や `retURL` など）が開き直したあとも残っていることを確かめる（AC2.1.5）。
7. 件数のしるしのない画面（設定のホームなど）と、Lightning の画面（`/lightning/` で始まる画面）には何も出ないことを確かめる（AC2.1.1）。
8. 本番組織に近い Sandbox と開発者組織の両方で、同じように動くことを確かめる（AC2.1.7）。

**一覧が見分けられないとき**: 件数バーが出ない一覧画面があれば、その画面のページ送りのリンクの形（クラス名や URL）を控え、`src/page/page-context.ts` の `PAGE_MARKERS` を直します（BR2.3）。表の上ではなく本文の先頭に出る場合は、`PAGE_MARKERS.listTableSelectors` を直します。

## 3. OFF にして再読み込み（US1.1）

1. `chrome://extensions` の sf-toybox の「詳細」→「拡張機能のオプション」で設定画面を開く。
2. 「一覧の表示件数の切り替え」を OFF にし、「保存しました」が 2 秒ほど出ることを確かめる（AC1.1.1）。
3. 設定画面を閉じて開き直し、OFF のままであることを確かめる（AC1.1.1）。
4. 開いていた Apex クラスの一覧を再読み込みし、件数バーが出ないことを確かめる（AC1.1.4）。
5. 開発者ツール（F12）の「ネットワーク」タブで、`page-size-bar.js` が読み込まれていないことを確かめる（NFR7.2）。
6. ON に戻して再読み込みし、件数バーがまた出ることを確かめる。
7. 設定画面の下部に「問い合わせ・不具合報告: リポジトリの準備中」が出ることを確かめる（リポジトリの URL が決まるまで。決まったあとはリンクが GitHub の Issue のページを開くこと。AC1.1.6）。
8. ブラウザの言語を英語にして設定画面を開き直し、英語で表示されることを確かめる（AC1.1.8）。

## 4. フォントと CSP のエラーの確認

1. Apex クラスの一覧で開発者ツールを開き、「コンソール」を見る。
2. `Refused to load`、`Content Security Policy`、`net::ERR_BLOCKED_BY_CLIENT`、`Denying load of chrome-extension://...` などの、件数バーの読み込みや表示を止めたことを示すエラーがないことを確かめる。
   - `web_accessible_resources` の `use_dynamic_url: true` によって `page-size-bar.js` が読み込めない場合は、このエラーが出ます。そのときは記録し、作者が対応を決めます。
3. 件数バーの文字と見た目（ボタンの枠、選択中のボタンの塗りつぶし、入力欄）が崩れていないことを確かめる。
   - 同梱している SLDS（2.264 系）はフォントのファイルを含まず、ブラウザの標準の文字（`--slds-g-font-family-base`）を使います。そのため、フォントの読み込みのエラーは出ないはずです。出た場合は記録します。
4. 「ネットワーク」タブで、拡張機能の外（`chrome-extension://` 以外）への読み込みが件数バーから起きていないことを確かめる（NFR3.1）。

## 5. 「最近のエラー」の確認

1. 設定画面の「最近のエラー」に、ここまでの確認の途中でエラーが記録されていないことを確かめる（cicd-pipeline.md「公開の流れ」2）。
2. エラーがあれば、時刻・ツールの識別子・種類・説明を控えて原因を調べる。中身に URL や Salesforce のデータが入っていないことも確かめる（security-design.md §5）。
3. 「消去」を押して一覧が空になることを確かめる。
