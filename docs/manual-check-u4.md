# 手での確認の手順 — U4 変更セットへの追加支援

自動テスト（`npm run test -- --coverage`）とビルドの確認（`npm run check:manifest`）が通ったあとに、**開発者組織か Sandbox** で、ビルドした拡張機能を手で動かして確かめます（team.md「Testing Posture」、U4 cicd-pipeline.md「U4 の手の確認」）。

- **本番組織では確かめません**。U4 は Salesforce を書き換える唯一のツールです（NFR8.1）。
- 確かめた結果は、日付・組織の種類（開発者組織／Sandbox）・Chrome の版と一緒に記録します。
- 拡張機能の読み込み方と共通の確認は `docs/manual-check.md` の「0. 用意」「1. 拡張機能の読み込み方」に従います。

## 0. 用意

1. 確認のための送信変更セットを 1 つ新しく作る（名前は `Test` で始める。例: `Test U4 確認`）。
2. 追加の候補にするため、Apex クラスやカスタム項目が数件ある組織を使う。親オブジェクトのある種類（カスタム項目など）と、ない種類（Apex クラスなど）の両方で確かめる。
3. 設定画面で「変更セットへの追加支援」が ON であることを確かめる（設定画面への登録は U3 で入る。U3 が入る前は、保存値がなければ ON として動く）。

## 1. 表示と追加前の確認（US4.1、AC4.1.1、AC4.1.9、BR1.1〜BR1.5）

1. 変更セットの詳細画面で「追加」を押し、「追加」画面を開く。
2. 候補の表のすぐ上に「sf-toybox 検索」のカードが出て、「追加先: <変更セットの名前>」が出ることを確かめる。
3. 開いた直後に「候補を読み込んでいます…」が出て、読み込み後に候補が名前の順で並ぶことを確かめる（NFR7.3）。
4. 種類の選択欄で種類を変えると、Salesforce が画面を読み込み直し、カードも新しい種類の候補で作り直されることを確かめる（BR1.3 の前提の確かめ）。
5. 開発者ツール（F12）の「コンソール」に、`Refused to load`・`Content Security Policy`・`Denying load of chrome-extension://...changeset-add-assist.js` などのエラーがないことを確かめる。
6. 設定画面で「変更セットへの追加支援」を OFF にして「追加」画面を再読み込みし、カードが出ず、「ネットワーク」タブで `changeset-add-assist.js` が読み込まれていないことを確かめる（AC4.1.9、NFR7.2）。確かめたら ON に戻す。

**種類が読めないとき**: カードに「この画面の種類を読み取れませんでした」が出る場合は、「追加」画面の種類の選択欄の HTML（`select` の `name`）を控え、`src/salesforce/markers.ts` の `CHANGE_SET_MARKERS.add.typeSelect` を直します。カードが表の上ではなく本文の先頭に出る場合は、`CHANGE_SET_MARKERS.add.candidateTable.table` を直します。

## 2. 検索と選択（AC4.1.2、AC4.1.3、AC4.1.6、AC4.1.8）

1. 検索欄に名前の一部を大文字・小文字を混ぜて入れ、その場で絞り込まれ、「一致: n 件」が変わることを確かめる。
2. カスタム項目の画面で「親オブジェクト」の選択欄が出て、名前と同時に絞り込めることを確かめる。Apex クラスの画面では選択欄が出ないことを確かめる。
3. 2 件を選んだあと、検索でその 1 件を隠し、「選択中: 2 件（うち 1 件は絞り込みで非表示）」と出ることを確かめる。
4. 一致しない文字を入れると「一致するコンポーネントがありません」が出て、検索を消すと選択が残っていることを確かめる。
5. 何も選んでいないとき、追加ボタンが押せず「追加するものを選んでください」が出ることを確かめる。
6. 検索欄で Enter を押しても追加が始まらないことを確かめる。

## 3. 追加（AC4.1.4、AC4.1.7、BR3.1〜BR3.5）

1. 3 件を選んで「選んだ 3 件を追加」を押す。確認画面は出ず、ボタンが「追加しています… (i / 3)」と進むことを確かめる。
2. 追加中は、検索・選択・ボタンが押せず、ボタンの近くに「追加しています。このページを離れると…」の文言が出ることを確かめる。追加中にボタンを何度押しても二重に追加されないことを、あとで変更セットの詳細画面で確かめる。
3. 終わると結果の欄が開き、見出しにフォーカスが移り、「追加できたもの (3)」に 3 件が出ることを確かめる。
4. 結果の欄が開いているあいだは、追加ボタン・検索・選択が押せないことを確かめる。
5. Escape（または「閉じる」）を押すと、「追加」画面が 1 回だけ読み込み直され、追加したものが Salesforce の候補の一覧から消えていることを確かめる。
6. 変更セットの詳細画面を開き、選んだ 3 件だけが入っていることを確かめる。

## 4. 途中の失敗と離れるときの確認（AC4.1.5、BR3.3、BR3.6）

1. 「追加」画面を 2 つのタブで開き、片方で候補 A・B・C を選ぶ。
2. もう片方のタブで、B を先に標準の「追加」で変更セットに入れておく。
3. 最初のタブで A・B・C の追加を押し、B のところで止まり、結果の欄に「追加できたもの（A）」「追加できなかったもの（B と理由）」「試さなかったもの（C）」が出ることを確かめる。理由が「追加できたか確かめられませんでした…」の場合は、変更セットの画面で B の状態を確かめる。
4. 多めの件数を選んで追加を押し、追加中にタブを閉じようとすると、ブラウザの「このページを離れますか」の確認が出ることを確かめる（「キャンセル」で残る）。
5. 設定画面の「最近のエラー」に、`changeset-add-assist` の記録が出て、変更セットや部品の名前が含まれていないことを確かめる。

## 5. 追加できない場合（AC4.1.10、BR1.2）

1. アップロード済みの変更セットの「追加」画面を開き、赤字で理由が出て、追加ボタンが押せないことを確かめる（Salesforce が「追加」画面を開かせない場合は、そのことを記録する）。
2. 変更セットを扱う権限のない確認用の利用者でログインし、同じ画面で理由が出て、追加ボタンが押せないことを確かめる。
3. 別のタブでログアウトしてから「もう一度試す」を押し、ログイン切れの理由が出て、「もう一度試す」が出ないことを確かめる。

## 6. 組織の種類（AC4.1.11）

1. 開発者組織と Sandbox の両方で、1〜4 が同じように動くことを確かめる。

## 7. 後片付け

1. 誤って追加したものは、変更セットの詳細画面の「削除」で取り除けることを確かめる（requirements.md の前提）。
2. **確認に使った変更セットは、確認のあとで削除する**。
